# Source–target cost-sensitive adaptation pilot

The fixed plan is in `protocol.json`. Run `python watershed_experiments/continue.py`; do not start another instance while it is running. The isolated environment overrides NumPy to1.26.4 to avoid observed NumPy2.0.2/Accelerate runtime warnings; global packages are unchanged. The driver treats runtime warnings as errors, first runs integrity tests, prepares spatial samples, runs the pilot and independently recomputes saved probabilities and metrics. Progress: `status.json` and `clean_run.log`; results: `pilot/REPORT.md`.

256-pixel non-test blocks,32-pixel interior buffer and3-pixel patch radius keep patch contexts inside their assigned subset. Original512-pixel test blocks and their sample files remain frozen. Non-test block assignment uses benchmark labels to require class support in adaptation/controller/development sets. This is disclosed simulator information, never an acquisition policy or test-driven choice. Zero reference labels mean unannotated, not a background class. Eligibility within reference support is part of this oracle-simulation benchmark, not deployment.

Five seeds share one spatial partition. Source training assumes available source annotations and subsamples at most200 examples per class. Source labels and700 controller labels are separate from the105→260→523→1046 acquired target labels.2000 further development labels are evaluation overhead. Reserved test features and labels are not opened by the pilot.

Training features are standardized on source training only. CORAL statistics use source training and unlabeled target acquisition pool only. No feature normalization, covariance, adaptive cost or query uses development or test data. Development scores are recorded after fitting, never fed to the controller. All reported decisions and risk scores use one fixed hypothetical cost matrix, not each method's changing coefficients.

The adaptive controller uses class-specific smoothed FNR on its700 labeled examples; classes with fewer than10 observations retain multiplier1. Controller and development samples include at least20 references per class; this enrichment requires benchmark label access and is not claimed to be a label-free deployment strategy. Development metrics use inverse class inclusion-probability weights to correct enrichment within the held-out development region. These are heuristic weights, not guaranteed risk bounds. Extra fixed baselines spend the same700 annotations directly on supervised fitting instead of control. Fixed/Adaptive entropy and risk queries separate the fitting and acquisition effects.

The first geometric pilot was rejected because development contained only water/vegetation. Its data and scores are preserved under `diagnostics/rejected_geometry_split` and marked invalid for seven-class comparison. Revised training has class-support gates before fitting; original test labels/results were not consulted to repair the non-test partition.

This is a small classical-model feasibility pilot, not an exact AdaRisk-Agent reproduction. No LLM calls, GPU training, calibrated probability guarantee, or measured ecological loss are claimed. Missing independent-scene validation, block/buffer sensitivity and cost-sensitivity checks remain explicit limitations. The protocol and code are hashed at start; changes require a fresh result folder.
